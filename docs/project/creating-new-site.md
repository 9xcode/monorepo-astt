# Creating a New Site

This guide walks you through creating a new niche site using the `@mtools/core` monorepo.

## Quick Start (5 steps)

### 1. Copy the template

```bash
cp -r sites/_template sites/my-new-site
```

### 2. Update `package.json`

Replace `@mtools/SITE_NAME` with your site's package name:

```json
{
  "name": "@mtools/my-new-site"
}
```

### 3. Fill in `src/config.ts`

Replace every `PLACEHOLDER_` token with your site's real values:

| Token | Replace with |
|---|---|
| `PLACEHOLDER_SITE_NAME` | e.g. `PDF Tools` |
| `PLACEHOLDER_DOMAIN` | e.g. `pdftools.app` |
| `PLACEHOLDER_PREFIX_` | e.g. `pdf_` (short, unique per site) |
| `PLACEHOLDER_TAGLINE` | e.g. `The fastest PDF tools on the web.` |
| `PLACEHOLDER_COMPANY` | Your company/entity name |
| `PLACEHOLDER_LOCATION` | e.g. `San Francisco, CA` |
| `PLACEHOLDER_SITE_DESCRIPTION` | The site's meta description |
| `PLACEHOLDER_NICHE` | e.g. `PDF`, `finance`, `text tools` |
| `PLACEHOLDER_AUTHOR_SLUG` | Default author slug (must match `src/content/authors/<slug>.md`) |
| `PLACEHOLDER_TWITTER` | Twitter handle without `@` |
| `PLACEHOLDER_TOPIC_1/2` | Schema.org `knowsAbout` topics |

### 4. Set up environment variables

```bash
cp sites/my-new-site/.env.example sites/my-new-site/.env
# Then edit .env and fill in real keys
```

### 5. Install and run

```bash
pnpm install
pnpm --filter @mtools/my-new-site dev
```

## Site Structure

A site only contains **site-specific** files. All shared logic (layouts, components, schemas, SEO, styles) lives in `@mtools/core`.

```
sites/my-new-site/
├── astro.config.mjs          # Thin wrapper: createAstroConfig(siteConfig)
├── svelte.config.js          # Standard vitePreprocess()
├── tsconfig.json             # Extends astro strict; $lib → ../../core/src/lib
├── package.json              # @mtools/core: workspace:*
├── .env                      # Local secrets — never commit
├── .env.example              # Safe template to commit
├── public/
│   ├── favicon.ico           # Your site's favicon
│   ├── favicon.svg           # SVG variant
│   ├── images/logo.png       # Site logo used in OG images
│   ├── fonts/                # Site-specific fonts (Roboto-Bold.ttf for OG)
│   └── robots.txt            # Updated with your actual domain
└── src/
    ├── config.ts             # All site values via createSiteConfig()
    ├── content.config.ts     # Astro content collections (schema factories from core)
    ├── env.d.ts              # App.Locals type declaration
    ├── content/
    │   ├── tools/            # One folder per tool with index.md
    │   ├── blog/             # One folder per post with index.md
    │   └── authors/          # One .md file per author
    ├── features/
    │   └── <tool-slug>/
    │       └── Widget.svelte # Svelte 5 tool widget
    ├── generated/            # Auto-generated by @mtools/widget-map (do not edit)
    │   └── widgets/
    ├── assets/
    │   └── images/
    │       └── authors/      # Author avatar images
    ├── styles/               # Site-specific theme CSS files
    │   └── slate.css         # Active theme (name must match config.ui.theme.name)
    └── components/
        └── integrations/
            ├── HeadScripts.astro   # Analytics scripts (injected in <head>)
            └── BodyScripts.astro   # Analytics scripts (injected before </body>)
```

## Adding a New Tool

1. Create `src/content/tools/<slug>/index.md` with frontmatter
2. Create `src/features/<slug>/Widget.svelte` with your Svelte 5 widget
3. Run `pnpm --filter @mtools/my-new-site dev` — the widget map is regenerated automatically

### Tool frontmatter reference

```yaml
---
title: "My Tool Name"
description: "Full description for the tool page."
shortDescription: "Shorter text for grids and cards."
category: "General"          # Must match a key in siteConfig.seo.categoryMappings
icon: "wrench"               # Lucide icon name
order: 10                    # Sort order in grids (lower = higher)
tags: ["tag1", "tag2"]
featured: false
isDraft: false
loadPriority: "only"         # "only" | "load" | "idle" | "visible"
---
```

## Adding a New Author

1. Create `src/content/authors/<slug>.md`:

```yaml
---
name: "Author Name"
role: "Content Writer"
shortBio: "Short bio for schema.org."
avatar: "../assets/images/authors/<slug>.jpg"
knowsAbout: ["Topic 1", "Topic 2"]
socials:
  twitter: "https://twitter.com/handle"
  linkedin: ""
  github: ""
  facebook: ""
---
```

2. Add their avatar image to `src/assets/images/authors/`

## Themes

Themes live in `sites/<site>/src/styles/` and are plain CSS files. The active theme is set in `src/config.ts`:

```ts
theme: {
  name: "slate",   // Must match src/styles/slate.css
}
```

To create a new theme, copy an existing theme file and modify the CSS custom properties.

All available theme files are listed in `core/src/styles/themes/` — you can copy any of them into your site's `src/styles/` directory.

## Turborepo Commands

```bash
# Dev a specific site
pnpm --filter @mtools/finance-tools dev

# Build a specific site
pnpm --filter @mtools/finance-tools build

# Build all sites
turbo build

# Build only affected sites (CI)
turbo build --filter=...[HEAD~1]

# Type-check a specific site
pnpm --filter @mtools/finance-tools check
```

## Key Architecture Notes

- **`virtual:site-config`** — All components access `siteConfig` via this virtual module (no prop drilling). It's registered by `createAstroConfig()` in the Vite plugin array.
- **`@mtools/core` alias** — The `@mtools/core` package is resolved as a workspace dependency. In dev/build, Vite resolves it directly to `../../core/` via the alias in `createAstroConfig()`.
- **`$lib` alias** — Points to `../../core/src/lib` — the shadcn-svelte primitives, Lucide icons, and utility functions.
- **`@active-theme` alias** — Points to `src/styles/<theme.name>.css` — your site's active Tailwind theme.
- **Widget map** — The `@mtools/widget-map` Astro integration runs automatically during every dev/build. It scans `src/features/` and `src/content/tools/` to auto-generate `src/generated/` files. In dev mode, it auto-regenerates when new tools/widgets are added. Never edit generated files manually.
